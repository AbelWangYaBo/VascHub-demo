# VascHub · 全血管数字平台（演示系统）

面向"全血管与结构性心脏病介入平台"的配套系统原型：把**病例、术式、器械（UDI）、随访、中心与术者、培训认证、数据治理**放在同一套数据上跑通。

> **关于本仓库**：个人独立开发的技术演示项目（作者 abel / [AbelWangYaBo](https://github.com/AbelWangYaBo)），与任何公司、组织无关。全部演示数据均为虚构，详见 [LICENSE](./LICENSE)。

## 怎么跑

```bash
python3 -m http.server 8765
# 打开 http://127.0.0.1:8765/index.html
```

零依赖，不需要 npm / Node，不需要联网。任何静态服务器都可以（Nginx、VSCode Live Server 等）。
在线演示（GitHub Pages）：https://abelwangyabo.github.io/VascHub-demo/

## 数据存在哪

浏览器 `localStorage`：

- `vaschub.store.v1` —— 病例（含患者授权）、方案、课程报名与认证（按演示身份隔离）、UDI 使用记录、审计留痕、当前身份
- `vaschub.basket.v1` —— 方案篮

换浏览器、清缓存或点顶栏"重置演示数据"即回到初始状态。

## 演示数据的边界

- 医院、术者、病例、器械批次全部虚构，只用于验证流程与数据结构，不代表真实机构或临床结果。
- 系统时间基准固定为 **2026-11-16**，逾期天数、UDI 效期剩余天数都按这一天计算。
- 患者姓名统一脱敏为"姓 + \*\*"，导出同样脱敏。

## 已验证的能力（端到端断言，0 控制台错误）

产品筛选与方案篮、术式详情、从术式新建病例（术者联动 / 器械预填 / 患者标识回读）、随访登记、刷新后持久化、全局搜索、UDI 使用登记、CSV 导出（CRLF + UTF-8 BOM，Excel 直接打开）、方案助手推荐、中心列表、课程报名、模块化学习与认证发放、审计留痕实时写入、中心 → 病例中心联动过滤、字段治理清单跳转病例、多身份切换（培训档案 / 审计 actor / 新建病例预填按身份隔离）、患者授权分项切换与撤回联动、合规控制矩阵（法规依据 + 牵头方 + 证据入口）、数据分级台账、RWE 队列审批流、销售身份数据使用红线。

预置演示数据（首次打开自动播种，升级演示数据版本时自动重播，当前 v4）：

- 14 例病例（覆盖四大领域、含逾期随访与待办场景），每例带患者分项授权（随访 / 院内科研 / RWE，10 例已授权 RWE）
- 5 个演示身份：3 位术者（领域层级各自独立：学习期 / 独立术者 / 带教导师）、1 位销售（产品线熟悉度）、1 位平台运营
- 7 条课程报名（跨身份、不同进度）、4 条认证记录
- 2 份已保存方案、18 条 UDI 记录、8 条审计日志

## 生产化时需要替换的部分

| 演示实现 | 生产建议 |
|---|---|
| localStorage | PostgreSQL + 服务端 API |
| data.js 静态数据 | 主数据服务（产品/术式/UDI 同步） |
| 手写 SVG 图表 | ECharts / 轻量图表库 |
| 无鉴权 | OAuth2/OIDC + 院内 CA 签名 |
| 单页静态站 | 前端构建（Vite）+ 容器化部署 |
